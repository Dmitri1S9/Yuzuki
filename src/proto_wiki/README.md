# proto_wiki — граф и параметры персонажа по тексту вики

Прототип проверяет один вопрос: хватает ли локальной `qwen3.5:9b`, чтобы извлечь граф отношений и параметры
персонажа **из текста вики**, а не из памяти модели. Один персонаж за запуск, без БД и Redis, существующий
пайплайн Yuzuki не затрагивается.

## Установка

```bash
# 1. Ollama и модель (Fedora: сначала драйвер NVIDIA, см. `nvidia-smi`)
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen3.5:9b

# 2. Зависимости (из папки Yuzuki/)
python3 -m venv .venv && source .venv/bin/activate
pip install -r src/proto_wiki/requirements.txt
```

Если `mwparserfromhell` не собирается (для Python 3.14 нет готового колеса, а `python3-devel` не установлен),
поставьте его без C-расширения: `WITHOUT_EXTENSION=1 pip install mwparserfromhell` — работает чуть медленнее,
для одной страницы это незаметно.

## Запуск

Из папки `Yuzuki/src` (или с `PYTHONPATH=src`):

```bash
python -m proto_wiki.cli \
    --input <папка или файл с текстом персонажа> \
    --character "Kyoka Jiro" \
    --params domain/parameters.json \
    --out <папка результатов>
```

| Ключ | Значение |
|---|---|
| `--input` | дамп `*_pages_current.xml`, файл с wikitext, plain text — или папка с одним из них |
| `--character` | имя персонажа = заголовок страницы в дампе |
| `--params` | `parameters.json` (по умолчанию `src/domain/parameters.json`) |
| `--out` | папка результатов и кеша |
| `--model` | по умолчанию `qwen3.5:9b` |
| `--ctx` | по умолчанию `32768`; если модель не влезает в VRAM, автоматически снижается до `16384` (пишется в лог) |
| `--fresh` | игнорировать кеш и пересчитать всё |

Адрес Ollama берётся из `OLLAMA_HOST` (по умолчанию `127.0.0.1:11434`). Для 8 ГБ VRAM могут помочь
`OLLAMA_FLASH_ATTENTION=1` и `OLLAMA_KV_CACHE_TYPE=q8_0` в окружении службы `ollama`.

Тесты (мок LLM, Ollama не нужна): `python -m pytest tests/proto_wiki`.

## Что делает

1. **Загрузка.** Из дампа берётся страница персонажа и подстраница `<Имя>/Relationships`. Wikitext разбирается
   `mwparserfromhell`; пропускаются разделы References, Navigation, Site Navigation, Gallery, External Links,
   See Also, Notes, Appearances (и `… Appearances`), Voice Actors вместе с подразделами. Из ссылок
   `[[Цель|алиас]]` собирается словарь алиасов: цель ссылки — канонический ID.
2. **Шаг 1** — замена местоимений и косвенных отсылок полными именами, один вызов на абзац. Результат длиной вне
   0.7–1.6 от оригинала отбрасывается (`REJECTED` в логе, берётся оригинал, `coref_ok: false`).
3. **Шаг 2** — тройки субъект–отношение–объект по закрытому списку отношений, один вызов на абзац, предложения
   пронумерованы. Тройки с `sentence_id` вне диапазона и с несовместимыми типами (`subject_type` не `Character`,
   тип объекта не подходит к отношению) отбрасываются и считаются в поле `dropped`.
4. **Граф** — нормализация имён через алиасы и части имени персонажа, склейка одинаковых троек со счётчиком,
   тип узла — самый частый.
5. **Шаг 3** — отдельный вызов на каждый параметр. Текст статьи и тройки идут в начале промпта, параметр в конце
   (Ollama переиспользует кеш префикса). Внешние знания модели запрещены промптом.
6. **Отчёт.**

## Выходные файлы (`--out`)

| Файл | Содержимое |
|---|---|
| `step1_coref.json` | абзацы: `section`, `original`, `resolved`, `coref_ok` (+ `error`, если вызов не удался) |
| `step2_triples.json` | все тройки с предложением-обоснованием и разделом; `errors` — упавшие абзацы; `dropped` — отброшенные тройки по причинам |
| `graph.json` | `center`, узлы `{id, type}`, рёбра `{source, target, relation, count}` |
| `graph.html` | интерактивный граф (vis-network, работает офлайн): персонаж закреплён в центре, цвет узла — по типу, легенда слева сверху |
| `step3_params.json` | результат по каждому параметру: `name`, `ordinal`, `tier`, `evidence`, `reason`, `status` |
| `report.md` | флаги «да» (T3) / «нет» (T1) / «не знает» (T2, unknown, evidence_not_found — с пометкой), ординалы с тиром и цитатой, раздел ERRORS |

`status`: `ok`; `evidence_not_found` — цитаты модели нет дословно в тексте (без учёта регистра и пунктуации,
от 10 символов), параметр уходит в «не знает»; `error` — вызов не удался после 3 ретраев или ответ не прошёл
валидацию (`tier: null`). **Сбой никогда не превращается в `unknown`** — он попадает только в ERRORS.

## Кеш

Шаги 1–3 кешируются в JSON внутри `--out`. Ключ кеша — хеш модели, текстов шаблонов шага и его входа, поэтому
правка промпта шага 3 пересчитывает только шаг 3, а шаги 1–2 читаются с диска. Параметры с `status: error`
при повторном запуске спрашиваются заново, остальные берутся из кеша. `--fresh` пересчитывает всё.

## Ограничения прототипа

- Инфобокс (`{{Character Infobox}}`) не разбирается: его поля (occupation, affiliation, …) в текст не попадают.
- Профильные поля (`profile` в `parameters.json`) не обрабатываются — только флаги и ординалы.
- Описания тиров ординалов берутся из существующих шаблонов `src/infra/prompts/templates/<prompt_template>.j2`
  (строки `[T3] …`), если они там есть; иначе шкала описана только как «T1 — низший, Tn — высший».

## Структура пакета

Отдельный сервис внутри `Yuzuki/src/proto_wiki/` — свои зависимости (`requirements.txt`), не часть Docker-образа
основного пайплайна. Слои — той же формы, что и у основного пайплайна (`domain/repository/services/infra`), но
не общий с ним код:

| Папка/файл | Роль |
|---|---|
| `domain/` | сущности без I/O: `Document`/`Paragraph`, `Param`, Pydantic-схемы LLM-ответов (`schemas.py`) |
| `repository/step_cache.py` | дисковый кеш JSON для шагов 1–3 — аналог репозитория БД |
| `infra/ollama_client.py` | единственный внешний сервис — клиент Ollama (`OllamaClient`) |
| `infra/prompts.py` | рендер Jinja2-шаблонов |
| `services/parsing/` | разбор XML-дампа/wikitext/текста и `parameters.json` |
| `services/coref/`, `services/triples/`, `services/params/`, `services/graph/`, `services/report/` | шаги 1–4 |
| `shared/decorators.py` | `@logged` — логирование только через декоратор, на внутренних (не на `ollama_client.py`) функциях |
| `main.py` | дирижёр — плоская последовательность вызовов шагов |
| `cli.py` | argparse + точка входа |
